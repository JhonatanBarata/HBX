## O QUE QUEBROU (o sintoma que sobrou — é FLUXO, não regra)
Backend certo, mas o caminho joga o usuário em **4 paredes** antes de poder pagar:
1. cadastra → tela "confirme seu e-mail" (sai do site, vai pro Gmail)
2. volta, clica no link → botão "Ir para o login"
3. loga → vira `pending_checkout`
4. cai no `BloqueioGate` → `/configuracoes?sec=Plano+e+cobrança` (a tela feia, sem saída)

**Causa raiz:** a confirmação de e-mail é um PORTÃO antes do checkout. O `CheckoutPanel` que
já existe na cena (`frontend/src/app/register/page.client.tsx:211`) só aparece quando vem
`access_token` — regra `showCheckout = Boolean(done?.access_token)` (linha 119). Em produção o
signup volta `pending_email_confirmation` SEM token → o checkout bonito nunca aparece. No
localhost funciona só porque `LOCAL_SIGNUP_AUTOCONFIRM` dá token na hora.
