## O QUE QUEBROU (o sintoma que sobrou — é FLUXO, não regra)
Backend certo, mas o caminho joga o usuário em **4 paredes** antes de poder pagar:
1. cadastra → tela "confirme seu e-mail" (sai do site, vai pro Gmail)
2. volta, clica no link → botão "Ir para o login"
3. loga → vira `pending_checkout`
4. cai no `BloqueioGate` → `/configuracoes?sec=Plano+e+cobrança` (a tela feia, sem saída)

**Causa raiz:** a confirmação de e-mail é um PORTÃO antes do checkout. O `CheckoutPanel` que
já existe na cena (`frontend/src/app/register/page.client.tsx:211`) só aparece quando vem
`access_token` — regra `showCheckout = Boolean(done?.access_token)` (linha 119). Em produção o
signup volta `pending_email_confirmation` SEM token → o checkout bonito nunca aparece. No
localhost funciona só porque `LOCAL_SIGNUP_AUTOCONFIRM` dá token na hora.

## COMO AS GRANDES FAZEM (o norte)
Padrão = **reverse trial / trial com cartão antecipado** (Netflix, Amazon Prime, SaaS B2B):
- **Uma cena só, sem sair** — conta + cartão no mesmo fluxo contínuo.
- **E-mail nunca trava** — confirmação vira faixa suave DENTRO do app, assíncrona.
- **Cartão capturado inline** pelo SDK do provedor (Mercado Pago Bricks), tokenizado no navegador.
- **Quem paga é admin — sem passo de permissão** antes de usar.
- **Cobra no fim do trial**, não na hora. Meta: **0 paredes.**

## VERDADE sobre "logar com Gmail e já puxar o cartão"
São **duas coisas diferentes**:
- **Login com Google** = IDENTIDADE (nome + e-mail JÁ verificado). NÃO compartilha cartão.
  Resolve a parede nº1 (e-mail do Google dispensa a confirmação).
- **"Cartão num toque"** = OUTRO produto: **Google Pay / carteira** no Mercado Pago Brick.
- Os dois empilhados = a experiência que o dono quer. **Hoje NÃO existe login social no código**
  (o "google" em `auth.service.ts` é só `acquisitionSource` = "como nos conheceu").
